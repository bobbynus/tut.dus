# ТУТ.DUS — памятка для Claude

Instagram **@tut.dus** и Telegram-канал **@tutdus** «Дюссельдорф на русском» для русскоязычных жителей:
что происходит сегодня, события, спорт, праздники, перекрытия, позже справочник врачей.
Владелец — bobbynus (живёт в Дюссельдорфе). Общаемся по-русски, просто и без жаргона.

Всё работает **на GitHub Actions бесплатно**: код и медиа лежат в репозитории, секреты в настройках репозитория.
Локальная машина нужна только для разработки и сборки постов.

## Правила владельца — соблюдать всегда

- **Лимиты Gemini не превышать.** Бесплатный тариф: квота сбрасывается в полночь по Тихоокеанскому времени
  (~09:00 Берлин), неудачные запросы тоже считаются. В `tools/gemini.py` стоят потолки ниже норм Google
  (gemini-3.5-flash 6/день из 20, flash-lite 120/день из 500) и журнал `data/gemini-usage.json`.
  Никаких циклов повторов. Для тестов — `NO_LLM=1`. Факты для рубрик Gemini не отдаём.
- **Никаких бесплатных лимитов не нарушать** (GitHub, Instagram 100 постов/сутки, Telegram).
- **В видео нет оригинального звука** — у футажей звук всегда вырезается (`-an`), музыка накладывается отдельно.
- **Статичные картинки в видео не анимировать** (без зума — текст должен читаться). Зум в `make_reel.py` только по `"zoom": true`.
- Постов в день немного, время — самое выгодное (см. `docs/content-plan.md`).
- Музыка трендовая, но не чересчур; если на слайдах много текста — без слов.
- **Только про город**, без личной жизни ведущих. Людей крупно в кадре не показываем.
- Дизайн v2: фото города на фоне, красный `#e2001a` только как акцент, шрифты Unbounded + Golos Text.
- Факты проверять по официальным источникам, источник и год писать на слайде. Не выдумывать.
- Уже опубликованное не переделываем. Историю git не переписывать без явной просьбы.
- Делать коммиты и пуш в `main` можно (это рабочий репозиторий владельца). PR не нужны.
- Если владелец просит «пока ничего не предпринимай» — только ответить.

## Как всё крутится

| Время (Берлин) | Что | Где |
|---|---|---|
| каждые 4 мин | «Часы»: публикуют посты, чьё время пришло; шлют черновики; догоняют пропущенные задачи | `clock.yml` → `tools/publish.py`, `tools/clock.py` |
| 08:00 | утренние сторис (видео 6 с с музыкой) в Instagram + Telegram | `posts/daily-YYYY-MM-DD/` |
| 09:30 | проверка здоровья → issue с меткой «внимание» → письмо владельцу | `health.yml` → `tools/health.py` |
| 10:15 | сбор событий → `data/events.json`, `data/events.md` | `events-collect.yml` → `tools/events/collect.py` |
| 20:30 | сторис на завтра | `daily-stories.yml` → `tools/stories/daily.py` + `to_video.py` |
| 1-го и 15-го | продление токена Instagram (нужен секрет `GH_PAT`) | `ig-refresh.yml` |

`clock.yml` — один длинный запуск (~5,7 ч), в конце перезапускает себя; cron GitHub ненадёжен, поэтому
остальные задачи страхуются из часов. Пауза автосторис — файл `AUTOPOST_PAUSED` в корне.

## Посты

Папка `posts/<имя>/` + `post.json` (формат — в начале `tools/publish.py`):
- `"status": "scheduled"` — публикует автоматика в `publish_at` (carousel / image / reel / story).
- `"status": "manual"` — **рубрики с музыкой**: через API музыку не добавить, поэтому бот в `send_at`
  шлёт владельцу черновик в личку Telegram (файлы без сжатия, подпись в блоке «Копировать», `music_hint`),
  владелец публикует сам; пост узнаётся по первой строке подписи и уходит в канал.
- `"status": "draft"` — не трогаем.
- После публикации появляется `published.json`, после Telegram — `telegram.json`.
- Медиа берутся по публичным ссылкам raw.githubusercontent.com — файл должен быть запушен.

## Сборка

```bash
cd design && npm ci                                   # шрифты
node render.cjs series/cifry-01.html ../posts/s01-cifry-1   # каждый <section class="slide" id> → PNG
python3 tools/make_reel.py posts/<имя>/reel.json      # Reels 1080×1920: картинки/футажи + музыка
python3 tools/stories/to_video.py posts/<папка>       # PNG-сторис → видео с музыкой
python3 tools/footage.py                              # какие футажи свободны (учёт в data/footage-usage.json)
DRY_RUN=1 POST=<имя> python3 tools/publish.py         # проверить пост без публикации
```
Нужны: Python 3.11+, ffmpeg, ImageMagick, Node 22 + Playwright (Chromium). Карусели — JPG 1080×1350;
промежуточные PNG сторис не коммитим (место в репозитории).

## Медиа

- `library/inbox/` — сюда владелец заливает фото/видео; `prepare-media.yml` убирает звук и метаданные (GPS),
  кладёт в `library/footage/own-*.mp4` и `library/photos/own-*.jpg`. Файлы, загруженные в корень репо, он не видит —
  их надо перенести в `library/inbox/`.
- `library/photos/backgrounds.txt` — фото-фоны для сторис. `library/music/` — треки с префиксами настроения
  (calm-, upbeat-, epic-, night-, vocal-). Кадры с Wikimedia Commons — с указанием автора в подписи.
- Футажи можно использовать повторно; в рилсах один кадр не чаще раза в 2–3 недели.

## События

`tools/events/sources.json` (страницы: JSON-LD или разбор Gemini Flash Lite), плюс модули:
`toubiz.py` (календарь Visit Düsseldorf через API toubiz, публичный токен со страницы, по дням на 3 недели),
`sports.py` (Fortuna — OpenLigaDB все турниры, DEG — iCal), `traffic.py` (автобаны, 15 км),
`calendar_de.py` (праздники NRW, торговые воскресенья), `annual.json` (большие ежегодные события).
`collect.py` склеивает дубли и под разными названиями (`same_event`). Разведка новых JS-календарей — workflow **Inspect page**.

## Секреты (в GitHub, локально не нужны)

`IG_ACCESS_TOKEN`, `IG_USER_ID`, `IG_APP_ID`, `IG_APP_SECRET`, `GH_PAT` (если задан), `GEMINI_API_KEY`,
`TG_BOT_TOKEN`, `TG_CHANNEL`. Бот — @tut_dus_bot; chat id владельца хранится зашифрованным в `data/telegram-owner.json`.
